# Ferry V1 readiness plan (owner, 2026-11-20: "make it the best damn app… get right to the point V1 is ready; don't cut V1")

Workstreams run in separate worktrees; each lands as reviewed PRs and pre-1.0 releases (0.x) through the normal release flow. No build is installed in /Applications except through a published release (the controller installs/validates).

## W1 Visual identity and polish
- App icon refresh (macOS 26 Icon Composer layers, light/dark/tinted), menu-bar template glyph, Finder sidebar/location icon for Ferry domains, device tiles (LinkRunner/EtherScope/phone/tablet glyphs), Help illustrations.
- DMG with a designed background and Applications alias; README hero image, feature screenshots (light/dark), a short GIF of drag-and-drop to a device.
- Menu visual pass: spacing, alignment, hover/pressed states, dark mode contrast, Increase Contrast, Reduce Transparency, larger text.

## W2 Connection robustness
- Wi-Fi connect/pair and Open in Terminal use the running server via host protocol (`host:connect:`, `host:pair:`) when one answers; never restart a foreign server.
- Agent spawn recovery: when launchd reports the agent's spawn failed (OS_REASON_CODESIGNING / EX_CONFIG), the app unregisters and re-registers it; extensions re-registered (`pluginkit`-equivalent via LSRegisterURL) after install/update.
- Local Network privacy (in progress, fix/local-network).

## W3 Test reliability and CI
- Injected clocks for the six time-bound ADB/wireless suites; remove CI `--no-parallel`; parallel suite green 20× locally.
- Release workflow resilience: retry notarytool on transient network errors (bounded), clear error on wrong certificate type (Installer vs Application) naming the certificate.

## W4 First-run and everyday UX
- First-run onboarding: welcome, turn on in Finder, connect a device, Get Android Platform Tools, Local Network permission — each step shown only when needed.
- Error states audit: every failure has plain wording, a next step and a Help link; empty states designed.
- Settings that matter only (none new unless a real need).

## W5 V1 audit and hardening
- Whole-repo review: security (IPC roles, file handling, downloads, zip), concurrency, accessibility (VoiceOver full pass by code), localization readiness, performance (startup, menu open, large folders), memory/leaks, logging privacy.
- Docs: README, user guide, Help, RELEASING, TESTING, privacy statement, licence notices (LGPL libmtp/libusb, Google SDK licence) complete.
- `docs/V1-READINESS.md`: what is done, what is verified how, and the owner-only hardware checks left.
