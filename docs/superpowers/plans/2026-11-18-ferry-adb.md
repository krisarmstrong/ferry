# Ferry ADB, Wi-Fi, Tools and Finder Sync (Plan 2b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve Android devices over ADB (USB and Wi-Fi) through the existing Finder location, keep MTP as the fallback, and add the ADB tools and a Finder Sync extension.

**Architecture:** A new `ADBTransport` module talks to the user's adb server over its TCP host protocol and conforms to `DeviceTransport`/`DeviceSession`. A `CompositeTransport` in the agent merges MTP and ADB scans per serial and picks the best method; `DeviceHub` swaps sessions when the method changes, so domains and item identities stay put. Tools are agent requests over the existing XPC; the menu bar app and a new Finder Sync extension are their only callers.

**Tech Stack:** Swift 6 (strict concurrency, actors), Network.framework (`NWConnection`) for the adb socket, Swift Testing, SwiftUI, FileProvider, FinderSync, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-11-17-ferry-design.md` (section "ADB", amended 2026-11-18).

## Global Constraints

- adb server at `127.0.0.1:5037`; never bundle or download `adb`; locate it only in `/opt/homebrew/bin/adb`, `/usr/local/bin/adb`, `~/Library/Android/sdk/platform-tools/adb`, `$ANDROID_HOME/platform-tools/adb` (agent environment), in that order.
- `adb` is run only via `Process` with an argument array: `start-server`, `pair <host:port> <code>`, `connect <host:port>`, `disconnect <host:port>`. No shell, no `PATH` lookup.
- Device shell commands quote every path argument with single quotes (`'` → `'\''`) and are built by one function; no other code builds shell strings.
- Method preference: ADB over USB > ADB over Wi-Fi > MTP. MTP code paths stay intact.
- Storage keys: `internal` for `/storage/emulated/0`, `volume:<UUID>` for `/storage/<UUID>`.
- Android 8 (API 26) is the floor; feature-detect `shell_v2`, `stat_v2`, `ls_v2` from `host-serial:<serial>:features`.
- Ferry never opens Apple (0x05AC) devices (unchanged); Wi-Fi never scans networks, only adb's own mDNS and remembered addresses.
- Every test run under `timeout`; no test writes over 64 MB; device tests only inside `Download/ferry-e2e` (created and removed by the test).
- Swift Testing, TDD with a saved RED for every behaviour change; `make lint fmt-check test` and `make app` clean (accepted warnings: the libmtp/IOKit ones only).
- Strings in the String Catalog; no NetAlly branding; MIT; no banned marketing vocabulary.

## Review Focus

1. **Method switch mid-transfer:** USB debugging is authorised (or revoked, or the cable pulled while Wi-Fi stays) during a copy. Expect: the transfer fails cleanly or completes; no partial left visible; Finder location and item identities unchanged after the switch. Test in Task 5.
2. **Same device seen twice:** one unit over USB and Wi-Fi at once, or MTP and ADB at once. Expect one Finder location, served by the preferred method, never two sessions writing. Test in Task 5.
3. **Unusual names over the shell:** names with `'`, `$`, backslash, leading `-`, newline, emoji. Expect exact round-trip or `.invalidName`; never a command that touches another path. Test in Task 3.
4. **Android 8 large files:** a file over 4 GB on a device without `ls_v2`. Expect the correct 64-bit size in listings and a full download. Test in Task 2 (fake) and Task 11 (device).
5. **adb server restarts or is killed** (the user runs `adb kill-server`). Expect devices drop to MTP or "ADB unavailable", then come back when the server returns, without restarting Ferry. Test in Task 4.

**Interfaces — Produces:**

- `enum ADBError: Error, Equatable { serverUnavailable, adbNotInstalled, failed(String), deviceGone(String), protocolViolation(String) }`
- `ADBStream` (actor over `NWConnection`): `read(exactly:)`, `write(_:)`, `close()`.
