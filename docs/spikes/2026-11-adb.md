# Spike: ADB on the LinkRunner alongside Ferry's MTP session

Date: 2026-11-18 · macOS 27.2 · adb 1.0.41 (platform-tools 37.0.1, Homebrew cask)

Device: NetAlly LinkRunner-100G, Android 8.1.0 (API 27), manufacturer property `freescale`.

## Results

| Question | Answer |
|---|---|
| ADB serial vs MTP serial | Same: `ro.serialno` = USB serial = `0123456789abcdef`. One `DeviceID` covers both. |
| MTP and ADB at once | Yes. With USB debugging on, the device is `18d1:4ee2` (`sys.usb.config` = `mtp,adb`): interface ff/ff/00 (MTP) held by FerryAgent, interface ff/42/01 (ADB) held by the adb server. Ferry's Finder location kept working. |
| Turning debugging on | The device kept `18d1:4ee1` (MTP only) until debugging was toggled with the cable in; then it re-enumerated as `4ee2` and showed "USB debugging connected". Neither a replug nor restarting Ferry's agent did it. The setup guide should say to toggle it with the cable plugged in. |
| Features | `cmd`, `stat_v2`, `shell_v2`. No `ls_v2`: listings need `STA2` for 64-bit sizes, as planned. |
| `shell_v2` exit status | Works (`exit 3` → rc 3). |
| Storage | `/storage/emulated/0` only (`/sdcard` → `/storage/self/primary`); no removable volume. `df -k` works (23.2 GB, `/data/media`). |
| Tools | toybox `stat` (`-c "%s %Y %F %n"` works), `mv`, `rm`, `mkdir`, `cp`, `df`, `find`, `ip`, `screencap`, `screenrecord`, `pm` all present. `exec-out screencap -p` returned a 720×1280 PNG. |
| Network for Wi-Fi ADB | `eth0` and `eno0` exist with no IPv4 (management port not on a network during the spike); `dummy0` has 10.11.12.13/30 and must be ignored. The `tcpip` path is untested until the unit is on a network. |

## Decision

Decision: proceed as planned, with these amendments:
- Task 6 guide: on the NetAlly board, toggle USB debugging off and on with the cable plugged in.
- Task 7: read the IPv4 of `eth0`/`eno0`/`wlan*` only, never `dummy*`, `lo` or tunnels; when none, say the unit needs a network first.
- Task 7/11 Wi-Fi verification needs the LinkRunner's management port or Wi-Fi on the Mac's network (owner).
- Task 5: the MTP storage key for internal storage must map to `internal`; confirm the MTP description/volume strings in Task 5 (read from the agent's storages, not a second libmtp open).

## EtherScope nXG over the network (2026-11-18)

- Android 8.1.0 (API 27), serial `fedcba9876543210`, same features (`cmd`, `stat_v2`, `shell_v2`).
- ADB already listens on TCP 5555 (`service.adb.tcp.port` = 5555, `persist.adb.tcp.port` empty)
  with no USB step: `adb connect 192.0.2.31:5555` showed `unauthorized` until the owner tapped
  Allow on the unit's "Allow USB debugging?" prompt, then `device`.
- adb lists it as `192.0.2.31:5555`; `ro.serialno` gives the real serial, as planned.
- It has several IPv4 addresses: `eth0` 192.0.2.31 (management), `wlan0` 192.0.2.169, `eno0`
  192.0.2.166 (test port), `dummy0` 10.11.12.13. Any of the first three may reach it.

Decision: Task 7 adds a third route, "Connect by address": the user types host[:port]
(default 5555), Ferry runs `adb connect`, and an `unauthorized` result shows "Allow on the
device". When a USB-ADB device already reports a TCP port (`service.adb.tcp.port`), Ferry
offers its addresses directly instead of running `tcpip`. Remembered addresses stay keyed by
serial.
